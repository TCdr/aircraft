1. Strobe double flash and beacon phase

Aircraft: A32NX and A380X  |  Where: EXT LT panel: STROBE ON, BEACON ON; outside view  |  Status: Checked in the sim by the user at night on both aircraft ("both look right", 2026-10-02).

What it is for

The FCOM gives no flash rates (A320 DSC-33-20-20, A380 DSC-33-30-20); the A380 FCOM only says that the strobes and the beacons alternate. The timing of the real lights comes from the Collins LED light data: a wing strobe double flash of 50 ms on, 60 ms off, 50 ms on, about 60 times a minute, the beacons flashing between the strobes. The FBW effects had a 50 ms gap (A32NX) and a 150 ms gap (A380X) in the double flash, and the A380X beacons flashed too close to the strobes.

2. Interior lighting presets save and load again

Aircraft: A32NX and A380X  |  Where: flyPad > Presets > Interior Lighting  |  Status: Tested in the sim by the user on the A32NX: save, load of a saved row, load of an unsaved row at 50 %: OK (2026-10-04). Not sim-tested: the load with no presets file yet (fresh install), and the A380X (same code). Native unit tests: extra-backend test/run_tests.sh.

What it is for

The flyPad interior lighting presets did nothing or the wrong thing on both aircraft, because of three bugs in the C++ extra-backend:

  • No preset was ever saved. The shared ini library refused the existing work folder (it read the mkdir result the wrong way), so every save failed silently and no presets file was written. It now accepts an existing folder. The FADEC fuel configuration save uses the same library and benefits too.
  • An unsaved row faded every light to off. Loading a row that was never saved left the target values unset, so every light, the PFD, ND, ECAM and MCDU brightness included, faded to 0. Such a row now loads the default preset, all lights at 50 %, as the flyPad page says. The A32NX default also had its DCDU and MCDU values in the wrong scale (0.5 instead of 50).
  • A load before the first save failed. With no presets file yet (fresh install), a load now gives the default 50 % preset instead of leaving the lights untouched.

What you should see

SituationWhat you should see
Save Preset on a row (aircraft powered)The current lighting levels are stored; the row loads them later, also after a sim restart.
Load Preset on a saved rowThe cockpit lights and display brightness fade to the saved levels.
Load Preset on a row never savedEvery light and display brightness fades to 50 %; nothing goes dark.
Automatic loading (Day / Dawn/Dusk / Night set to a row)The selected row loads as above: its saved levels, or 50 % if it was never saved.

Limitations and why

LimitationWhyWhat to do
Presets saved before the fix do not exist.No save ever reached the file before.Save the rows again once.
The aircraft must be powered to save or load.Stock flyPad rule.Power the aircraft first.
A full MSFS restart is needed after an update.The extra-backend WASM module changes.Restart the sim after installing.

How to use

  1. Power the aircraft and set the cockpit lights and display brightness as you like.
  2. Open flyPad > Presets > Interior Lighting, optionally rename a row, and press Save Preset on it.
  3. Later, press Load Preset on that row to get the same lighting back.

How to test

#Do thisExpected result
1A32NX (or A380X) powered, on the ground. Set the panel and flood lights and the display brightness to clearly different levels. flyPad > Presets > Interior Lighting: press Save Preset on row 1 and confirm.The save completes.
2Change the lights, then press Load Preset on row 1.The lights and displays fade back to the saved levels.
3Press Load Preset on a row that was never saved.Every light and display brightness fades to 50 %: the PFD, ND, ECAM and MCDU stay readable.
4Restart the sim, power the aircraft and load row 1 again.The saved levels come back (the presets file was written).
